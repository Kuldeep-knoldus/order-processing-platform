# Expense REST API

## Project overview

This project is a Spring Boot 4 REST API for recording and querying business expenses. It is intentionally organized as a small production-style service so the request flow is easy to review:

`Controller -> Service -> Repository -> MySQL database`

The API uses an Expense use case, with validation at the HTTP boundary, DTOs between the API and domain model, consistent error responses, pagination, filtering, sorting, and an aggregate reporting endpoint.

## Entity and API model

`Expense` has six fields:

| Field | Type | Purpose | Validation |
| --- | --- | --- | --- |
| `id` | `Long` | Database-generated identifier | Generated by JPA |
| `description` | `String` | What the expense was for | Required |
| `category` | `String` | Expense classification | Required |
| `amount` | `BigDecimal` | Monetary value | Greater than `0.00` |
| `expenseDate` | `LocalDate` | Date the expense occurred | Required, not in the future |
| `ownerEmail` | `String` | Person responsible for the expense | Required, valid email |

The database entity is `com.nashtech.expenseapi.expense.Expense`. The API accepts `ExpenseRequest` and returns `ExpenseResponse`, so persistence details do not leak into the HTTP contract.

## API endpoints

| Method | Endpoint | Description |
| --- | --- | --- |
| `POST` | `/api/expenses` | Create an expense; returns `201 Created` |
| `GET` | `/api/expenses` | List expenses with filters, paging, and sorting |
| `GET` | `/api/expenses/{id}` | Get one expense; returns `404` when absent |
| `PUT` | `/api/expenses/{id}` | Replace an existing expense |
| `DELETE` | `/api/expenses/{id}` | Delete an expense; returns `204 No Content` |
| `GET` | `/api/expenses/summary?category=Travel` | Sum expenses for a category |
| `GET` | `/swagger-ui.html` | OpenAPI interactive documentation |

### Create and update body

```json
{
  "description": "Cloud hosting",
  "category": "Technology",
  "amount": 49.99,
  "expenseDate": "2026-09-20",
  "ownerEmail": "buyer@example.com"
}
```

### Search, pagination, and sorting

All list filters can be combined. Matching is case-insensitive:

```text
/api/expenses?category=Technology&description=cloud&ownerEmail=buyer@example.com&page=0&size=20&sortBy=amount&direction=DESC
```

Supported sort fields are `expenseDate`, `description`, `category`, `amount`, and `ownerEmail`. Page numbers start at zero and page size is limited to 100.

- Spring Initializr-style Gradle project with Java 21

- Complete create, read, update, and delete operations

## Run locally

The default configuration expects MySQL on `localhost:3306`:

```sql
CREATE DATABASE expense_db;
CREATE USER 'expense_user'@'localhost' IDENTIFIED BY 'expense_password';
GRANT ALL PRIVILEGES ON expense_db.* TO 'expense_user'@'localhost';
```

From this directory, use the wrapper so the required Gradle version is selected automatically:

```powershell
.\gradlew.bat clean test
.\gradlew.bat bootRun
```

The API runs at `http://localhost:8090`. Override the connection when needed:

```powershell
$env:DB_URL = "jdbc:mysql://localhost:3306/expense_db"
$env:DB_USERNAME = "expense_user"
$env:DB_PASSWORD = "expense_password"
```

Hibernate uses `ddl-auto: update` for this learning assignment. In a production system, use a migration tool such as Flyway or Liquibase instead.

## Docker

Build and run from this directory:

```powershell
docker build -t expense-api:local .
docker run --rm -p 8090:8090 `
  -e DB_URL=jdbc:mysql://host.docker.internal:3306/expense_db `
  -e DB_USERNAME=expense_user `
  -e DB_PASSWORD=expense_password `
  expense-api:local
```

The Dockerfile builds the application with Gradle and runs the resulting jar on Eclipse Temurin Java 21 as UID `10001`.
